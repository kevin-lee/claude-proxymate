* **Request Filter**: filter from traffic in the **Messages** tab (#50)

  The **Filter** sheet from 0.4.0 (#33) is where the whole rule set is reviewed, but reaching it meant leaving the captured request that showed the badge, skill or text to stop sending. The **Messages** tab now has inline controls that write to the same `request-filter.json`. The address-bar **Filter** button, the sheet (if open) and the **Messages** tab update after each change.

  - **Badge menu**: Clicking a **Rule**, **CLAUDE.md**, **Memory** or **Skills** badge opens a menu with **Remove from future requests** (or **Keep in future requests** if the badge is already removed), **Remove all rules / docs / skills** and **Expand**. The filter key comes from the same parsers the filter uses, not from the badge label. Badges that don't map to a filter category, such as a plain system-reminder, the Memory fallback badge and slash commands, still expand on click.
  - **Per-skill removal**: The expanded **Skills** badge shows one row per skill with a ✕ toggle to remove or keep that skill.
  - **Removed state on badges**: While **Filtering** is on, a badge removed by the saved config is struck through with a "removed · ~N tok" note, so the user can see what the next request will leave out.
  - **Selection to text rule**: Selecting text in the user's own typed text shows a menu with **Text**, **Regex** and **Tag `<name>`** (Tag appears only when the selection is exactly one tag element) and **Add**. **Add** appends a rule scoped to *Both*.
  - **Request filter bar**: A bar above the message list shows the **Filtering** switch, the rule count, the tokens removed from the selected request, **+ Text rule** (opens the sheet with a new rule focused) and **Manage rules** (opens the sheet).

  The proxy binary and the config format are unchanged.

## Fixes

* Keep the settings file's own indentation when writing `ANTHROPIC_BASE_URL` (#44)

  Starting the proxy in Global mode wrote `env.ANTHROPIC_BASE_URL` into `~/.claude/settings.json` with the `"env": {` line pushed to column 0 and the inserted key indented by 4 spaces in a file that uses 2. Removing the key did the same, and the VS Code, VS Code Insiders, VSCodium and Cursor settings files were affected the same way. Tab-indented files ended up with mixed tabs and spaces.

  - The indentation is now detected from the file itself (spaces with their width, or tabs). When nothing can be detected, `~/.claude/settings.json` uses 2 spaces, the same as the Claude Code CLI, and the VS Code family uses the file's `editor.insertSpaces` and `editor.tabSize`, then 4 spaces.
  - A key line damaged by earlier releases is re-indented the next time the proxy writes or removes the key. Only the managed property is touched.
  - Known gap: when an earlier release created `env` from scratch, it also pushed the line just before `env` to column 0. That line is not repaired.

* Make the `claude-proxymate` CLI exit when the desktop app stops it or closes (#47)

  The native proxy could outlive the desktop app and keep holding its port, so the next start failed with `Address already in use`.

  - The proxy now gives graceful shutdown 5 seconds and then exits. Before, a `SIGTERM` that arrived during an in-flight request could wait up to the 300-second request timeout.
  - A new opt-in `--exit-on-stdin-close` flag makes the proxy exit when its parent process goes away, including `SIGKILL` and Force Quit. The desktop app passes it. Running the binary directly from a terminal is unaffected.
  - The desktop app now waits for the proxy process to actually exit, sending `SIGTERM` and then `SIGKILL` after 3 seconds, before it reports the proxy as stopped. Starting the proxy while the previous one is still stopping is refused with a message instead of racing it for the port.
  - Quitting the app waits for the proxy to exit. Quit time went from about 3.4 seconds to about 0.3 seconds.

## Internal Housekeeping

* Fix the flaky duplicate-entry property in `VsCodeEnvSpec`.

  `testDuplicatesHandled` drew its two ports independently, so they could be equal, which changed the correct answer and failed the hard-coded expectation. The second port is now the first plus or minus a nonzero delta, so the two can never collide.

* Use kittens for the `Eq`, `Hash` and `Show` type classes, and add a `CanEqual` instance in `ParentLink`.
