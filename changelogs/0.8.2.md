# [0.8.2](https://github.com/kevin-lee/claude-proxymate/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am13) - 2026-11-22

## Fixes

* The proxy did not start on a Mac without a Homebrew OpenSSL formula, and the app did not show why (#95)

  The proxy binary loaded `libcrypto` from the Homebrew folder of the build machine (`/opt/homebrew/opt/openssl@4/lib/libcrypto.4.dylib` on arm64, `/usr/local/opt/openssl@3/lib/libcrypto.3.dylib` on x64). On a Mac without that formula, `dyld` stopped the proxy before it started, and the app showed only "stopped".

  - **No Homebrew dependency**: The proxy now gets the two `libcrypto` functions that `http4s-crypto` uses (`EVP_Digest` and `EVP_get_digestbyname`) from Apple CommonCrypto, which is part of `libSystem`. The binary now loads only `/usr/lib/libSystem.B.dylib` and `/usr/lib/libcurl.4.dylib`.
  - **Cause in the app**: When the proxy fails to start or stops unexpectedly, the app shows "The proxy stopped unexpectedly: " with the exit reason and the last lines of the proxy's error output, for example the `dyld` message. The text is available in English and Korean.

* A long response through the proxy hung for minutes and then failed (#100)

  The proxy read the full response from Anthropic before it sent anything to Claude Code, so Claude Code got no data until the model was done. libcurl also stopped every transfer after 300 s, so a response that took longer failed with a 502 error, and the output was lost.

  - **Streaming**: The proxy now sends the status, the headers and each part of the body to Claude Code when they arrive.
  - **Timeouts**: The 300 s limit on the total transfer is removed. The proxy now has a connect timeout of 30 s and an idle limit of 600 s (less than 1 byte/s for 600 s), the same as the default `API_TIMEOUT_MS` of Claude Code.
  - **Cancel**: When Claude Code disconnects (for example when you press Esc), the proxy stops the request to Anthropic.
  - **`HEAD` requests**: The `HEAD /api/hello` request that Claude Code sends at start no longer fails.
  - A transfer that fails after the headers now fails the response, so Claude Code does not get a response that looks complete.

* Two requests that arrived in the same millisecond got the same capture id, so the app showed the wrong response for one of them (#99)

  This happened more often when several Claude Code instances, or parallel subagents, used the proxy at the same time. Now each request gets a unique id, also in the same millisecond. Claude Code was not affected.

* The request list showed the capture time in UTC, not in the local time of the Mac (#101)

  For example, on a Mac in UTC+11, a request sent at 22:16 showed `11:16`. The list now shows the local time. The time also has a tooltip with the full local date, time and offset, for example `2026-11-15 22:16:04 UTC+11:00`.

## Internal Housekeeping

* Check the libraries that the proxy binary loads in CI and in the release build (#95)

  - New `scripts/check-macos-load-commands.sh` fails when a binary loads a library outside `/usr/lib/` and `/System/Library/`. The build and release workflows run it on the test binary, on the release binary and on the packaged app in the DMG and the zip.
  - The build and release workflows now run `proxyServer/test` on macOS and `electron/test`.
  - New end-to-end test `scripts/e2e/proxy-exit-test.js` (`playwright-core`) checks a start failure, a crash after start, and a normal start and stop in the app.

* The renderer tests now run in jsdom, and new tests cover the event handlers of the user interface (#100)

* The renderer registers the proxy capture handlers in one place and finds the selected capture with one function (#105)

  Before, the renderer had two copies of the handlers and nine copies of the code that finds the selected capture. New tests cover the handlers.

* The proxy event `request_captured` has `capturedAt` (epoch milliseconds) in place of `ts` (`HH:mm:ss`) (#101)
