# [0.8.0](https://github.com/kevin-lee/claude-proxymate/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am11) - 2026-11-04

## New Features

* Self-update: check, download, verify, install and relaunch (#84)

  Before, the app only showed a `↑ vX.Y.Z` badge when a newer release was available. Now the app finds, downloads, verifies and installs a new release by itself, with [`electron-updater`](https://www.electron.build/auto-update) and Squirrel.Mac. An app installed with Homebrew updates itself the same way as an app installed from the disk image (DMG). The arm64 build gets only the arm64 update, and the x64 build gets only the x64 update.

  - **Update pill**: When an update is found, a pill next to the version shows `↑ Update to vX.Y.Z`. A click on it opens a panel with the installed and new versions, **Download and install** and **What's new**. While the update downloads, the pill shows the progress.
  - **Restart**: When the update is ready, the pill shows `Restart to update vX.Y.Z`. Its panel has **Restart now**, **Later** and **What's new**. **Restart now** stops the proxy and restores the Route Claude settings before the app restarts. If you do not restart, the update installs at the next quit. The app never restarts by itself.
  - **Auto update**: The `ℹ` popover shows the update status, **Check now**, the last check time and the checkbox **Update automatically when the app starts**. This checkbox is on by default. With it on, the app downloads an update at start and then shows the restart pill.
  - **App menu**: **Check for Updates…** comes after **About Claude Proxymate**. It opens the `ℹ` popover and checks now.
  - **Errors**: A background check that fails is silent apart from a log line. A check that you start shows the error. An update whose code signature does not match the installed app is rejected.
  - **Localization**: All new text is available in English and Korean.
  - **Privacy**: The old badge and its call to the GitHub API are removed. The renderer's Content Security Policy (CSP) `connect-src` is now `'self'` only.

  **Note**: Apps on 0.7.0 or older do not have the updater. Update them to 0.8.0 one time by hand, or with `brew upgrade --cask claude-proxymate`. After that, the app updates itself.

## Fixes

* Price Claude Sonnet 5.5 and Claude Haiku 5.5 with their own rates, and refresh the price list date (#73, #86)

  The rate table is checked against the [Claude pricing page](https://platform.claude.com/docs/en/about-claude/pricing) on 2026-11-04. Every other rate, the fast mode and US-only inference multipliers, and the web search price still match the page.

  - **Claude Sonnet 5.5**: `claude-sonnet-5-5` now has its own tier at $2 input / $10 output per million tokens, with cache reads at $0.10. Before, it was priced only by accident as Sonnet 5. An unrecognized Sonnet model name such as `claude-sonnet-6` now falls back to the Sonnet 5.5 rates as the current Sonnet.
  - **Claude Haiku 5.5**: `claude-haiku-5-5` had no tier, so it was priced as Haiku 4.5 at $1 / $5, which is 10x too high. It now has its own tier, with two rate cards that the prompt length selects. The prompt length is all input tokens of a request, including cache reads and cache writes.

    | Prompt length        | Input | 5m cache write | 1h cache write | Cache read | Output |
    |:---------------------|------:|---------------:|---------------:|-----------:|-------:|
    | Up to 100,000 tokens | $0.10 |         $0.125 |          $0.20 |      $0.01 |  $0.50 |
    | Over 100,000 tokens  | $0.50 |         $0.625 |             $1 |      $0.05 |  $2.50 |

    The fast mode and US-only inference multipliers apply on top of the selected rate card. An unrecognized Haiku model name such as `claude-haiku-6` now falls back to the Haiku 5.5 rates as the current Haiku.
  - **Long prompt note**: When a capture was billed with the long prompt rate card, the token popover and the **Analysis** cost card show a note saying so, in English and Korean.
  - **Pricing reference**: The pricing date is now 2026-11-04.

## Internal Housekeeping

* Move the release secrets into the `release` environment and require signing for releases (#83)

  - The `build` and `tap` jobs of the release workflow use the `release` environment. Its deployment rule allows only `v*` tags. A `workflow_dispatch` on a branch is refused at `build`, and nothing is published.
  - `build` fails before it builds anything if one of the signing, notarization or Google Analytics (GA) secrets is missing. The check tests presence only and never prints a value.
  - Verify DMG always requires a Developer ID signature, notarization and a stapled ticket. The ad-hoc signed fallback for releases is removed.
  - `pr-labeler.yml` gives `pull-requests: write` to its job only. The top level is now `contents: read` only.

* Publish the self-update files with each release (#84)

  - Each build job verifies, checksums and uploads the app `zip` and its blockmap next to the DMG.
  - The `release` job writes one `latest-mac.yml` for both architectures with the new `scripts/write-latest-mac-yml.sh`, and publishes it with the release.
  - `scripts/update-cask.sh` adds `auto_updates true` to the Homebrew cask.
  - `CLAUDE_PROXYMATE_UPDATE_FEED_URL` points the updater at a local feed for testing.

* Run `electron-builder` with `--publish never` in the build and release workflows (#88)

  The GitHub `publish` config added in #84 made `electron-builder` try to publish in CI, and the `electron-mac` job failed because `GH_TOKEN` is not set. The release workflow had the same problem, so the next `v*` release would also have failed. `app-update.yml` is still embedded in the app, so self-update is not affected.

* The header version now comes from `app.getVersion()`. The old code read `build-info.json`, which no build step creates (#84)
