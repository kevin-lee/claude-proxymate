# [0.4.0](https://github.com/kevin-lee/claude-proxymate/issues?q=is%3Aissue%20is%3Aclosed%20milestone%3Am5) - 2026-09-09

## New Features

* Add **Request Filter** - strip rule files, docs, skills and text from requests before they reach Claude (#33)

  <img width="800" height="543" alt="Claude Proxy - Request Filter (2)" src="https://github.com/user-attachments/assets/942efd8c-d742-467e-a7e7-62536f18c1b2" />

  Claude Code injects content the user never typed into every request - global and project `CLAUDE.md`, rule files under `.claude/rules/`, memory files and the list of available skills - and re-sends it on every turn. A new **Filter** button in the address bar opens a sheet that decides what is removed from a request before the proxy forwards it to Anthropic. Only `messages[]` is touched, so `system`, `tools` and everything else pass through untouched.

  - **Rules**, **Docs** and **Skills** each get a *Keep all / Remove selected / Remove all* mode plus a checklist. Rules are the `Contents of …/rules/*.md` sections, Docs are every other `Contents of <file>` section (`CLAUDE.md`, `MEMORY.md`, …), and Skills are the entries of the "skills are available for use with the Skill tool" reminder. Files arriving through `@` mentions or tool results are what the user actually asked for, so they are never touched.
  - **Text rules** come in three kinds: *Text* (literal), *Regex* (RE2 syntax on the native proxy, so no lookahead, lookbehind or backreferences - a rule that fails to compile is skipped and listed in the sheet) and *Tag* (removes `<name …>…</name>` including the tag). Each rule is scoped to *Typed* (the user's own text), *Claude* (assistant replies echoed back as history) or *Both*. A text block that becomes empty is dropped and a message that becomes empty is replaced by `[filtered]`, so the request stays valid.
  - The sheet works **before the first capture**: the Electron main process scans `~/.claude` (rules, `CLAUDE.md`, `projects/*/memory/MEMORY.md`, `skills/*/SKILL.md`), and items seen in captured requests are merged in as they show up. *Remove all* is what catches items that have not been seen yet. A ticked file that is no longer on disk is kept and ignored - it may belong to another project - and shown as *not found* with no pop-up.
  - The sheet previews the token change against the last captured request, and every filtered capture carries a report: the Messages tab shows removed items as struck-through "removed · ~N tok" rows, and the Request tab shows the body that was actually sent.

  The config is persisted as `request-filter.json` under the app's `userData` directory and passed to the proxy as `--filter-config <path>`. The proxy re-reads the file on every request, so **Save** applies without restarting the proxy. Changing rules mid-session invalidates Claude Code's prompt cache once.

  The filtering engine itself is pure and lives in `claudeproxymate.core.filter`, shared by all three runtimes: the native proxy applies it, the Electron main process validates with it, and the renderer previews a draft against the last capture.

## Fixes

* `CLAUDE.md` section boundaries ran to the end of the enclosing system-reminder, so a section could swallow the reminder's own trailer (`# userEmail`, `# currentDate` and the closing `IMPORTANT` line). Section end bounds now stop before it, and the filter and the section badges share one labeling function, so they always agree. (#33)

* Both forwarders now drop the incoming `Content-Length` / `Transfer-Encoding` headers and send the real length of the possibly rewritten body. (#33)
